# 可迁移能力清单

这份文件不是在罗列“我会什么软件”，而是把两年训练里真正练出来的、能换个题目继续用的东西写清楚。

## 1. 从不透明的评分系统里反推规则

仿真软件只给总分，不给扣分明细。要提分，只能自己把总分的构成拆开。
拆的过程是：固定其他变量、单独改一项、看分数怎么动，反复几轮之后能画出评分项的权重结构。
这次拆出来的结论是：质量分是稳态维持型指标，参数落在区间内持续给分，出区间就掉分，与操作速度关系不大。

这套动作换个场景仍然成立——任何“只告诉你结果、不告诉你原因”的评价体系，都可以用同样的方法反推。

## 2. 把过程变成可回溯的记录

每次操作全程录屏，文件名直接编码“场景 + 耗时 + 得分”，例如 `固定床/反应器超温25秒99.5.mp4`。
这样不需要额外维护台账，文件名本身就是一条数据记录，可以批量解析成表格。

配套的是一张进度表，按单元记录开车、停车两个科目的成绩与耗时。7 个单元里 5 个停车满分，靠的就是这张表能看出哪个单元还欠着。

## 3. 版本化迭代，而不是推倒重来

操作方案留了 6 个版本（v3.01 → v6.0），每版只改一处，改完记录为什么改。
好处是任何一步退步都能定位到是哪一版动的；坏处是要多花时间维护旧版本。

最终版本里，塔板温度、泡点温度、回流负荷都写成了具体数值区间，任何人拿到都能照着做。

## 4. 先建立稳态，再进入考核窗口

这是整套方法里最核心的一条。

仿真评分和真实开车有一个共同点：评价的是“在稳定状态下能维持多久”，不是“多快把流程走完”。
所以正确的顺序不是从第一步按部就班做到最后，而是先锁定影响稳态的几个关键参数、提前把它们建立起来，再进入考核区间。

## 5. 把方法写成别人能用的东西

单个项目的经验如果只留在自己脑子里，价值有限。
这个仓库做的事就是把上面四条整理成文档、数据集和脚本，让下一个从零开始的人不必重复摸索。

---

这些能力都来自仿真训练场景，但都不是仿真专有的。真正带走的是：**拆规则、留记录、控版本、找稳态、写下来。**
